# ID 생성기 요구사항

- 상태: 승인 (2026-09-20)
- 작성일: 2026-09-20
- 대상: `@cp949/random` 0.1.0의 `./id` 영역. 로드맵 R2, R3의 세부 요구를 정의한다.
- 이 문서가 정하지 않는 것: 함수 이름, 시그니처. 단계 시작 시 작성하는 design spec이 정하고, 확정된 R2·R3 몫은 구현 뒤 `docs/api/id.md`에 기록한다. 오류 클래스 이름은 6절의 결정 기록에 있다.

## 1. 목적과 범위

ID 생성기는 프로젝트마다 다시 만들고 감싸 쓰는 ID 생성 코드를 대체한다. 흔한 변형(접두사, 길이, 문자 집합, 형식, 충돌 회피)은 옵션으로 직접 제공하고, 같은 설정을 재사용하는 생성기를 한 줄로 만든다.

생성기는 두 종류다.

| 종류           | 난수원                     | 예측 | 예                                    |
| -------------- | -------------------------- | ---- | ------------------------------------- |
| 무작위 ID      | `getRandomValues` (CSPRNG) | 불가 | UUID v4·v7, nanoid, 문자·숫자 ID      |
| 순환·카운터 ID | 없음                       | 가능 | int32 순환 ID, 접두사 + base36 카운터 |

기능 추가 여부는 로드맵 §1의 판정 기준으로 정한다: 반복되는 wrapper 사례가 있는가, 같은 증거 체계로 검증되는가, 의존성 없이 기존 확장 지점에 맞는가.

### 1.1 용어

- 생성기: 인자 없이 호출하면 다음 ID를 돌려주는 함수 `() => T`.
- 팩토리: 옵션을 받아 생성기를 돌려주는 함수.
- leaf 함수: 옵션이 적은 최소 진입점(예: `nanoid`). 번들 크기를 최소로 유지한다.
- 편의 진입점: 옵션이 풍부한 진입점.
- wrap: 범위의 끝에서 반대쪽 끝으로 돌아가는 동작.
- 범위 크기: `max - min + 1`.

### 1.2 포함

3절(무작위 ID)과 4절(순환·카운터 ID)의 요구를 0.1.0에 포함한다.

### 1.3 후속 후보

수요 증거가 확인되면 개별 단계로 승격한다.

| 항목                                                                              | 지금 제외하는 이유                                                                                                                 |
| --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 충돌 분석(`probability`, `entropy`, `requiredLength`, `analyze`)                  | `bits` 옵션(RND-1)이 크기 산정 요구를 직접 충족한다. 반복 구현 사례가 확인되지 않았다.                                             |
| 순환 ID의 wrap 감지(`nextWithInfo`, `cycle()`), `requireFullCycle`, `cycleLength` | 상태 API를 `peek`/`reset`으로 한정했다(SEQ-5). wrap 감지가 필요한 사례가 확인되지 않았다.                                          |
| 비동기 충돌 검사(`isTaken`이 Promise 반환)                                        | 동기 검사만 지원한다(RND-1). 저장소 조회가 필요하면 호출자가 반복한다.                                                             |
| ULID, human-friendly ID(단어 사전), `validate.*` 세트                             | 사례가 확인되지 않았다. 단어 사전은 번들 크기 부담이 있고, 형식 검증은 정규식 한 줄로 대체된다.                                    |
| `bigint` 순환·카운터 ID                                                           | ES2019 타입 설정과 정적 게이트에서 허용되는지 확인되지 않았다. 프로브로 확인한 뒤 정한다. int32·uint32 범위는 `number`로 충분하다. |

### 1.4 제외

| 항목                                                                                                          | 제외 이유                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 네임스페이스 객체 API(`random.*`, `id.*`, `sequence.*`), 토큰 전용 함수, `preset`/`recommend` API, `unsafe.*` | 확정된 leaf 함수 + subpath 구조와 tree shaking에 맞지 않는다. 재현 가능한 난수는 `./state`가 다룬다.                                                     |
| 도메인별 커스텀 오류 클래스 다수                                                                              | 오류를 3종으로 한정한다(C-6).                                                                                                                            |
| 정의와 상태를 분리하는 모델(Definition/Cursor), Cursor Store·TTL, clone·fork·compare, snapshot·restore        | 공통 형태 `() => T`를 유지한다(C-1). 호출처별 상태는 팩토리를 반복 호출해 만들고, 복원은 `start`로 한다(SEQ-5, SEQ-7).                                   |
| 포맷 템플릿(`{date}-ORD-{sequence:06}`)과 parse, 주기 초기화 번호(일·월·연)                                   | 벽시계, 타임존, 영속 저장이 필요하다. 접두사·패딩·진법 옵션(SEQ-8)으로 대체한다.                                                                         |
| 시간 + counter 수열형 ID(`timestamp`, `monotonic`)                                                            | `uuidv7` 단조(RND-5)와 timestamp 접두사(RND-1)가 대체한다.                                                                                               |
| 분산·외부 저장소 기반 ID(Snowflake, external sequence, range allocation, persistence adapter, 어댑터 패키지)  | 저장소 I/O, 비동기 API, 실패 정책이 필요하다. 로드맵 R2의 wrapper 사례에 없고 단일 패키지 제약에 어긋난다. 실제 사례가 확인되면 R9 후보로 다시 검토한다. |
| 수학 수열(등차, 등비, 피보나치)                                                                               | 난수와 무관하며 판정 기준의 첫 조건(반복되는 ID·난수 wrapper 사례)을 충족하지 않는다.                                                                    |

## 2. 공통 요구

- **C-1. 형태.** 모든 ID 생성기는 인자 없는 함수 `() => T`다. 진입점은 (a) 최소 leaf 함수, (b) 옵션이 풍부한 편의 진입점, (c) 옵션을 고정해 생성기를 돌려주는 팩토리로 나눈다.
- **C-2. 상태.** `./id` 영역의 상태는 인스턴스 단위다. 인스턴스끼리 상태를 공유하지 않는다. 전역 가변 상태는 `uuidv7`의 기본 factory(첫 사용 시 생성)뿐이다. 동기 호출은 중간 상태를 노출하지 않는다. 상태를 가진 생성기는 난수원이 예외를 던져도 상태를 바꾸지 않는다.
- **C-3. 난수원.** 무작위 ID는 `globalThis.crypto.getRandomValues`만 쓴다. `Math.random`을 호출하지 않는다. 미지원 환경(`globalThis.crypto` 없음, `getRandomValues`가 함수가 아님, `globalThis.crypto` 접근 예외)에서는 `SecureRandomUnavailableError`를 던진다. import 시점에 crypto에 접근하지 않는다. 순환·카운터 ID는 난수원을 쓰지 않는다.
- **C-4. 주입.** byte source와 clock(`now`)을 생성 시점에 주입할 수 있다. 주입한 source의 결과에는 보안 보증이 없음을 타입과 문서로 구분한다.
- **C-5. 입력 검증.** 지원하지 않는 옵션 값·조합은 조용히 무시하지 않고 `RangeError`로 실패한다. 검증은 팩토리는 생성 시점에, 일회성 호출 함수는 호출 시점에 한다. 길이·개수 상한은 spec에서 정하며, 무제한 메모리 할당을 허용하지 않는다. 숫자 옵션은 `number` 타입의 safe integer만 받는다(문자열과 소수는 `RangeError`). 옵션 객체는 검증 시점에 한 번만 읽어 복사한다.
- **C-6. 오류 종류.** 라이브러리가 직접 던지는 오류는 `RangeError`, `SecureRandomUnavailableError`, 충돌 회피 상한 초과 오류(이름은 spec에서 정한다) 3종으로 한정한다. 타입 위반도 `RangeError`이며 `TypeError`를 던지지 않는다. `getRandomValues`와 주입 함수가 던진 오류는 감싸지 않고 그대로 전파한다.
- **C-7. 무편향.** 문자·정수 선택은 rejection sampling으로 무편향을 보장한다. `byte % n` 방식을 쓰지 않는다.
- **C-8. 환경.** Chrome 75 이상, Worker와 SSR에서 동작한다. DOM 전역과 `node:crypto`를 쓰지 않는다. 런타임 의존성이 0이다. import 시점에 side effect가 없다.
- **C-9. 번들.** leaf 함수만 import하면 다른 생성기 코드가 번들에 들어가지 않는다. export마다 번들 크기 한도를 정하고 CI에서 검사한다. 한도 수치는 첫 측정 후 정하며 문서에 기록한다.
- **C-10. 종류 구분.** 무작위 ID와 예측 가능한 순환·카운터 ID는 이름, 타입, 문서로 구분한다. 한 함수가 둘을 겸하지 않는다. subpath를 분리할지는 spec에서 정한다.
- **C-11. 문서화.** 공개 함수마다 입력 검증, 오류, 결과값이 계약인지 여부를 문서에 적는다.

## 3. 무작위 ID 요구

- **RND-1. 범용 무작위 ID 진입점.** 다음 옵션을 wrapper 없이 지원한다. 옵션 이름은 spec에서 정한다.
  - 접두사와 구분자
  - 길이 또는 엔트로피(`bits`) 중 하나. 동시에 지정하면 `RangeError`. `bits`는 문자 집합 크기에서 목표 엔트로피를 만족하는 최소 길이를 계산한다.
  - 문자 집합: 이름 있는 preset(base64url(URL-safe), base62, base36 소문자, 숫자, 모호한 글자를 뺀 가독성용)과 사용자 정의. 사용자 정의 문자 집합은 코드 포인트 단위(`Array.from` 기준)로 다루며 중복 검사와 크기 범위도 같은 기준이다. 중복 문자, 짝 없는 surrogate, 크기 범위 위반은 `RangeError`.
  - 대소문자와 그룹화(예: `K7XM-4P9Q-T3DR`)
  - 식별자·HTML id에 안전한 시작 문자(첫 글자를 문자로 제한)
  - 정렬 가능한 timestamp 접두사(고정 폭, 사전순이 시간순)
  - 충돌 회피: 동기 `isTaken` 검사와 재시도 상한. 상한을 넘으면 오류.
- **RND-2. 숫자 ID.** 자릿수를 지정한 숫자 문자열(앞자리 0 유지, 각 자리 무편향)과 범위 정수를 만든다.
- **RND-3. `nanoid(length = 21)`.** base64url(URL-safe) 64자(`A-Za-z0-9-_`)를 쓴다. alphabet 인자는 받지 않는다. 커스텀 alphabet은 `randomString`을 쓴다.
- **RND-4. `uuidv4`.** `getRandomValues` 단일 경로로 만든다. `crypto.randomUUID`는 Chrome 92에서 추가되어 Chrome 75 하한에서 쓸 수 없다. version/variant 비트를 설정하고, 형식 옵션(대시 유무, 대소문자)을 제공한다. 바이트 배열은 `parseUuid(uuidv4())`로 얻는다.
- **RND-5. `uuidv7`.** 단조다. `createUuidv7Factory({ now?, randomBytes? })`로 독립 인스턴스를 만든다. 동작 세부(같은 ms의 `rand_a` counter 증가, 고갈 시 +1ms, clock rollback)는 README "확정된 제약"을 따른다.
- **RND-6. UUID 유틸.** `isUuid`(strict), `parseUuid`, `stringifyUuid`를 제공한다.
- **RND-7. 팩토리.** RND-1~RND-5의 옵션을 고정해 `() => string`을 돌려주는 팩토리를 제공한다.

## 4. 순환·카운터 ID 요구

- **SEQ-1. 순환 ID 생성기.** 정수 범위 `[min, max]`를 `step`씩 이동하고, 범위를 벗어나면 반대쪽 끝으로 wrap하는 `() => number`다.
  - `max`는 필수이고 `min`의 기본값은 0이다. `step`의 기본값은 1이다.
  - `start`의 기본값은 범위가 0을 포함하면 0, 아니면 `min`이다. 근거: SEQ-4의 프리셋 규칙을 일반 규칙으로 표현했다.
- **SEQ-2. 입력 검증.** `min`, `max`, `start`, `step`은 모두 safe integer여야 한다.
  - `min > max`, 범위 밖의 `start`, `step === 0`은 `RangeError`다.
  - 범위 크기가 `Number.MAX_SAFE_INTEGER`를 넘으면 `RangeError`다. 근거: 넘으면 modulo 계산에서 정밀도가 손실된다.
  - 중간 계산도 safe integer 안에 머문다.
- **SEQ-3. step.** 음수 `step`(감소 순환)을 허용한다. `|step|`이 범위 크기보다 커도 modulo로 동작한다. `step`과 범위 크기가 서로소가 아니면 일부 값만 순환한다. 이는 오류가 아니며 문서에 적는다.
- **SEQ-4. 프리셋.** `int8`, `uint8`, `int16`, `uint16`, `int32`, `uint32`를 제공한다. 범위는 각 타입의 범위와 같고 시작값은 0이다. 예: `int32`는 `[-2147483648, 2147483647]`이고 `2147483647` 다음이 `-2147483648`이다.
- **SEQ-5. 상태 API.** `peek()`은 상태를 바꾸지 않고 다음 반환값을 돌려준다. `reset(start?)`은 초기 위치 또는 지정한 위치로 되돌리며 범위 밖이면 `RangeError`다. 그 밖의 상태 API는 두지 않는다. 복원은 저장해 둔 값을 `start`로 넘겨 한다.
- **SEQ-6. 고유성 없음.** 순환 ID는 고유하지 않다. wrap 후 값 재사용은 정상 동작이며 오류가 아니다. 사용 중인 값과의 충돌은 소비자가 관리한다. 예측 가능하며 보안 용도가 아니다.
- **SEQ-7. 인스턴스 독립.** 인스턴스는 서로 상태를 공유하지 않는다. 호출처별 카운터는 팩토리를 호출처마다 호출해 만든다.
- **SEQ-8. 문자열 카운터 ID.** 카운터 값을 진법으로 인코딩하고 접두사와 0 패딩을 붙인 `() => string`이다.
  - 카운터 규칙은 SEQ-1~SEQ-3과 같다.
  - 기본 범위는 `[0, Number.MAX_SAFE_INTEGER - 1]`다. 범위 크기가 SEQ-2의 상한과 같다.
  - 진법은 2~36이다.
  - `min < 0`이면 `RangeError`다. 근거: 부호가 접두사·패딩과 섞이는 것을 막는다.
- **SEQ-9. 의존성.** 순환·카운터 ID는 난수원과 clock을 쓰지 않는다. import 시점에 예외가 없다.

## 5. 보장과 검증

### 5.1 보장 표

모든 생성기는 메모리 상태만 가지며 영속하지 않는다.

| 생성기                   | 고유성                                                                 | 시간 정렬                                     | 예측 불가                        |
| ------------------------ | ---------------------------------------------------------------------- | --------------------------------------------- | -------------------------------- |
| `nanoid`, 범용 무작위 ID | 확률적(길이·문자 집합에 의존). `isTaken` 사용 시 검사 범위 안에서 보장 | X                                             | O (주입 source를 쓰면 보증 없음) |
| `uuidv4`                 | 확률적(랜덤 122bit)                                                    | X                                             | O                                |
| `uuidv7`                 | 확률적                                                                 | 인스턴스 안에서 단조, ms 단위                 | 부분(timestamp 노출)             |
| 순환 ID                  | wrap 전까지 인스턴스 안에서 고유, wrap 후 재사용                       | X                                             | X                                |
| 문자열 카운터            | 순환 ID와 같음                                                         | 접두사·고정 폭이 같으면 wrap 전 사전순이 값순 | X                                |

### 5.2 문서화 요구

- 5.1의 보장 표를 API 문서에 싣는다.
- UUID는 인가 수단이 아니다.
- 순환·카운터 ID는 예측 가능하며 보안 용도가 아니다. wrap 후 중복은 소비자가 관리한다.
- 생성기 상태는 프로세스·Worker·탭 사이에 공유되지 않고, 재시작하면 초기화된다.
- 사용처별 레시피를 싣는다: 요청 ID, 사용자 ID, 파일 이름, HTML id, 인증 코드.

### 5.3 검증

- **VER-1.** 옵션 조합별 출력 길이·문자·형식을 정규식과 고정 byte 주입으로 검증하고, 문자 빈도 통계로 균등성을 검증한다.
- **VER-2.** 잘못된 옵션이 `RangeError`로 실패하는지 검증한다: 중복 alphabet, `bits`와 `length` 동시 지정, 음수 길이, `min > max`, `step: 0`, safe integer 초과, 범위 크기 초과. 추가로 숫자 옵션의 문자열(`'10'`)·소수(`2.1`)·`NaN`, 호출마다 다른 값을 돌려주는 `valueOf`·getter 옵션, 이모지처럼 UTF-16 코드 유닛이 둘인 문자를 포함한 alphabet의 길이와 중복 검사를 검증한다.
- **VER-3.** rejection 분기를 경계 byte 주입과 mutation 테스트로 검증한다. `uuidv4`의 version/variant 마스크를 제거한 mutation은 실패해야 한다.
- **VER-4.** `uuidv7`의 timestamp 레이아웃, 같은 ms 대량 생성의 단조성, counter 고갈, clock rollback을 결정적 clock·byte 주입으로 검증한다. byte source가 예외를 던진 뒤에도 상태가 바뀌지 않고 다음 호출이 정상 동작하는지 검증한다.
- **VER-5.** 충돌 회피를 검증한다. 작은 문자 집합과 짧은 길이로 충돌을 유도해 재시도와 상한 초과 오류를 확인한다.
- **VER-6.** 순환 ID를 검증한다.
  - `max` 다음 `min`, int32 경계(`2147483647` 다음 `-2147483648`)
  - 작은 범위의 전체 순회(중복 없음), 범위 크기를 `gcd(|step|, 범위 크기)`로 나눈 값만큼 호출한 뒤 원위치로 복귀
  - 음수 `step`, `step`이 범위 크기보다 큰 경우, 단일 값 범위(`min === max`)
  - 인스턴스 독립성
- **VER-7.** 게이트를 통과한다.
  - `Math.random` 호출 금지 lint
  - `globalThis.crypto`가 없어도 import가 성공하고, 무작위 ID의 첫 호출이 `SecureRandomUnavailableError`로 실패
  - dist의 ES2019 문법 검사
  - export별 번들 크기 한도(C-9)
  - `getRandomValues`가 65,536바이트를 넘는 요청에서 예외를 던지는 stub으로 큰 요청 검증(실제 브라우저와 같은 한도)
  - Chromium 75 smoke(릴리스 게이트)
- **VER-8. 사용성 시험.** 다음 사례가 wrapper 없이 라이브러리 호출 한 줄로 만들어진다는 것을 fixture로 검증한다. 요구 사례로만 쓰며 기존 구현과의 호환은 목적이 아니다.
  1. 접두사 ID
  2. 시각과 무작위를 합친 요청 ID
  3. N자리 숫자 코드(앞자리 0 유지)
  4. 식별자·HTML id에 안전한 ID
  5. 충돌 회피 ID
  6. 대시 없는 UUID
  7. int32 순환 ID
  8. 접두사 + base36 카운터 ID (예: Blockly의 `getNextUniqueId`는 `'blockly-' + (nextId++).toString(36)`을 반환한다)
  9. 그룹화된 가독성 코드(`K7XM-4P9Q-T3DR`)

`R3`로 시작하는 행과 `카운터 대소문자`, `순환·카운터 결과값`, `reset()` 무인자 행은 2026-09-21, 나머지는 2026-09-20 확정이다.

## 7. 미결정

- 사용성 사례 보강: 기존 프로젝트의 ID wrapper 전수 조사가 끝나지 않았다. 결과에 따라 VER-8의 사례와 RND-1의 옵션 목록을 보강한다. R2는 VER-8의 무작위 ID 사례(1~6, 9번), R3는 순환·카운터 ID 사례(7, 8번)로 확정하며, 조사 결과로 옵션이 더 필요하면 후속으로 추가한다(옵션 추가는 비파괴).
- 이 문서 밖으로 넘긴 항목: 정수 함수의 `size` 옵션(1차원만)과 `bool`의 확률 인자는 R4·R5 spec에서 정한다.

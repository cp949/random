# TRP-002 실제 dist를 지우고 다시 만드는 테스트가 병렬 테스트를 간헐적으로 실패시킨다

- 상태: ACTIVE
- 적용 조건: vitest가 테스트 파일을 병렬 워커로 실행하는 동안 한 테스트가 저장소의 실제 `packages/random/dist`를 삭제·재생성하고, 다른 테스트가 같은 `dist`를 읽을 때(`pnpm pack`, dist import 등).

## 오해하기 쉬운 신호

- 실패가 전체 실행 15회 중 1회 정도로 드물다. 다시 실행하면 통과해서 일시적 문제로 넘기기 쉽다.
- 실패한 테스트의 코드는 맞다. 오류는 `ENOENT ... lstat '.../packages/random/dist'`처럼 파일이 없다는 내용이다.
- 실패하는 테스트와 원인 테스트가 서로 다른 파일이다.

## 원인

- 한 테스트가 실제 `dist`를 지우고 `tsc`로 다시 만드는 짧은 구간에 다른 테스트가 같은 패키지를 `pnpm pack`한다.

## 탐지/회피

- 테스트는 저장소의 실제 산출물을 변형하지 않는다. 빌드 정리 테스트는 임시 패키지에서 실제 `build` 스크립트 문자열을 실행한다.
- 실제 `dist`를 읽는 검사는 `pnpm verify`의 순차 단계에서만 실행한다.
- 간헐 실패는 전체를 반복 실행해(`for i in $(seq 1 25); do pnpm test; done`) 실패한 테스트 이름을 수집해서 원인을 좁힌다.
